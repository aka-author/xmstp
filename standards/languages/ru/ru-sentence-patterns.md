# Требования к техническому тексту на русском языке. Фигуры описания

## Перечисления

### Выбор способа оформления

| ID          | Требование                                                                                                        |
|-------------|-------------------------------------------------------------------------------------------------------------------|
| R.RUTF.0100 | Перечисление должно быть оформлено как перечисление частей одного предложения или как перечисление предложений.   |
| R.RUTF.0110 | Все элементы одного перечисления должны быть оформлены одним способом.                                            |
| R.RUTF.0120 | Элементы, представляющие части одного предложения, должны начинаться со строчной буквы.                           |
| R.RUTF.0130 | Элементы, представляющие части одного предложения, должны разделяться точками с запятой.                          |
| R.RUTF.0140 | Последний элемент перечисления, представляющего одно предложение, должен заканчиваться точкой.                    |
| R.RUTF.0150 | Элементы, представляющие самостоятельные предложения, должны начинаться с прописной буквы и заканчиваться точкой. |

| ID          | Указание                                                                                                           |
|-------------|--------------------------------------------------------------------------------------------------------------------|
| D.RUTF.0160 | Оформляйте перечисление как одно предложение, если его элементы представляют слова или словосочетания одного ряда. |
| D.RUTF.0170 | Оформляйте элементы как самостоятельные предложения, если каждый элемент передает законченное сообщение.           |

| ID          | Пример                                         |
|-------------|------------------------------------------------|
| E.RUTF.0180 | Исправление смешанного оформления перечисления |

В следующем перечислении первый элемент оформлен как часть одного предложения, а второй — как самостоятельное предложение.

```markdown
В зоопарке содержатся следующие животные:

- слоны;
- Бегемоты.
```

Если элементы представляют части одного предложения, перечисление должно быть оформлено следующим образом:

```markdown
В зоопарке содержатся следующие животные:

- слоны;
- бегемоты.
```

Если элементы представляют самостоятельные назывные предложения, перечисление должно быть оформлено следующим образом:

```markdown
В зоопарке представлены животные двух видов:

- Слоны.
- Бегемоты.
```

| ID          | Пример                                  |
|-------------|-----------------------------------------|
| E.RUTF.0190 | Исправление последнего знака препинания |

В следующем перечислении последний элемент заканчивается точкой с запятой.

```markdown
В зоопарке содержатся следующие животные:

- слоны;
- бегемоты;
```

Последний элемент перечисления, представляющего одно предложение, должен заканчиваться точкой.

```markdown
В зоопарке содержатся следующие животные:

- слоны;
- бегемоты.
```

### Выбор падежа

| ID          | Требование                                                                                                            |
|-------------|-----------------------------------------------------------------------------------------------------------------------|
| R.RUTF.0200 | Наименования предметов, действий, признаков и состояний в элементах перечисления должны стоять в именительном падеже. |
| R.RUTF.0210 | Вводное предложение не должно требовать употребления элементов перечисления в косвенном падеже.                       |
| R.RUTF.0220 | Однотипные элементы перечисления должны быть выражены одинаковыми грамматическими формами.                            |

| ID          | Пример                                            |
|-------------|---------------------------------------------------|
| E.RUTF.0230 | Исправление падежной формы элементов перечисления |

В следующем фрагменте предлог *из* требует употребления элементов перечисления в родительном падеже.

```markdown
Система состоит из:

- анализатора;
- модуля принятия решений.
```

Вводное предложение должно быть перестроено так, чтобы элементы перечисления стояли в именительном падеже.

```markdown
В состав системы входят следующие компоненты:

- анализатор;
- модуль принятия решений.
```

| ID          | Пример                                       |
|-------------|----------------------------------------------|
| E.RUTF.0240 | Исправление неоднородных грамматических форм |

В следующем фрагменте элементы выражены существительными, инфинитивом и предложением.

```markdown
Предусмотрены следующие операции:

- шифрование данных;
- проверять подпись;
- резервное копирование;
- пользователь восстанавливает данные.
```

Все элементы должны быть выражены существительными в именительном падеже.

```markdown
Предусмотрены следующие операции:

- шифрование данных;
- проверка подписи;
- резервное копирование;
- восстановление данных.
```

### Формулирование вводных предложений

| ID          | Требование                                                                                               |
|-------------|----------------------------------------------------------------------------------------------------------|
| R.RUTF.0300 | Вводное предложение должно быть построено так, чтобы элементы перечисления стояли в именительном падеже. |
| R.RUTF.0310 | Составное глагольно-именное выражение не должно использоваться вместо равнозначного простого глагола.    |
| R.RUTF.0320 | Краткое причастие должно быть согласовано с определяемым существительным в роде и числе.                 |

| ID          | Указание                                                           |
|-------------|--------------------------------------------------------------------|
| D.RUTF.0330 | Для описания состава объекта используйте модель, приведенную ниже. |

`В состав {объекта в родительном падеже} входят следующие {компоненты в именительном падеже множественного числа}:`

| ID          | Указание                                                                             |
|-------------|--------------------------------------------------------------------------------------|
| D.RUTF.0340 | Для описания результатов выполненного действия используйте модели, приведенные ниже. |

| Значение              | Модель                                                                                                           |
|-----------------------|------------------------------------------------------------------------------------------------------------------|
| Учет факторов         | *При {действии в предложном падеже} учтены следующие {факторы в именительном падеже множественного числа}:*      |
| Использование данных  | *При {действии в предложном падеже} использованы следующие {данные в именительном падеже множественного числа}:* |
| Применение методов    | *При {действии в предложном падеже} применены следующие {методы в именительном падеже множественного числа}:*    |
| Принятие допущений    | *При {действии в предложном падеже} приняты следующие {допущения в именительном падеже множественного числа}:*   |
| Выбор решений         | *Для {цели в родительном падеже} выбраны следующие {решения в именительном падеже множественного числа}:*        |
| Установка ограничений | *Для {объекта в родительном падеже} установлены следующие {ограничения в именительном падеже мн. числа}:*        |

| ID          | Пример                                       |
|-------------|----------------------------------------------|
| E.RUTF.0350 | Замена составного выражения простым глаголом |

В следующем фрагменте учет факторов выражен составной конструкцией *были приняты во внимание*.

```markdown
При оценке рисков были приняты во внимание следующие факторы:

- вероятность отказа оборудования;
- продолжительность восстановления;
- стоимость простоя.
```

Конструкция *были приняты во внимание* должна быть заменена краткой формой *учтены*.

```markdown
При оценке рисков учтены следующие факторы:

- вероятность отказа оборудования;
- продолжительность восстановления;
- стоимость простоя.
```

| ID          | Пример                                          |
|-------------|-------------------------------------------------|
| E.RUTF.0360 | Исправление согласования во вводном предложении |

В следующем фрагменте причастие не согласовано с существительным *данные*.

```markdown
При расчете использовано следующие исходные данные:

- стоимость оборудования;
- продолжительность эксплуатации;
- нормативный срок службы.
```

Причастие должно стоять во множественном числе.

```markdown
При расчете использованы следующие исходные данные:

- стоимость оборудования;
- продолжительность эксплуатации;
- нормативный срок службы.
```

| ID          | Требование                                                                                                       |

## Требования

### Формулирование обязательства

| ID          | Требование                                                                                                 |
|-------------|------------------------------------------------------------------------------------------------------------|
| R.RUTF.0700 | Обязательство должно быть выражено словом *должен* в форме, согласованной с субъектом требования.          |
| R.RUTF.0710 | С существительным мужского рода должна использоваться форма *должен*.                                      |
| R.RUTF.0720 | С существительным женского рода должна использоваться форма *должна*.                                      |
| R.RUTF.0730 | С существительным среднего рода должна использоваться форма *должно*.                                      |
| R.RUTF.0740 | С существительным во множественном числе должна использоваться форма *должны*.                             |
| R.RUTF.0750 | Предписанное действие должно быть выражено инфинитивом после слова *должен*.                               |
| R.RUTF.0760 | Слова *следует*, *необходимо*, *требуется* и *надлежит* не должны использоваться для выражения требований. |

| ID          | Указание                                                       |
|-------------|----------------------------------------------------------------|
| D.RUTF.0770 | Для выражения требования используйте модели, приведенные ниже. |

| Форма субъекта      | Модель                                                          |
|---------------------|-----------------------------------------------------------------|
| Мужской род         | *{Субъект} должен {выполнить действие}.*                        |
| Женский род         | *{Субъект} должна {выполнить действие}.*                        |
| Средний род         | *{Субъект} должно {выполнить действие или обладать свойством}.* |
| Множественное число | *{Субъекты} должны {выполнить действие}.*                       |

| ID          | Пример                                                 |
|-------------|--------------------------------------------------------|
| E.RUTF.0780 | Замена безличной конструкции формой со словом *должен* |

В следующем предложении обязательство выражено безличным словом *необходимо*.

```markdown
Необходимо сохранить результаты проверки.
```

Субъект должен быть назван, а обязательство должно быть выражено согласованной формой слова *должен*.

```markdown
Система должна сохранить результаты проверки.
```

### Формулирование запрета

| ID          | Требование                                                                                          |
|-------------|-----------------------------------------------------------------------------------------------------|
| R.RUTF.0800 | Запрет должен быть выражен отрицательной формой слова *должен* или словом *запрещено*.              |
| R.RUTF.0810 | В конструкции со словом *запрещено* наименование участника должно употребляться в дательном падеже. |

| ID          | Указание                                                    |
|-------------|-------------------------------------------------------------|
| D.RUTF.0820 | Для выражения запрета используйте модели, приведенные ниже. |

| Тип запрета               | Модель                                        |
|---------------------------|-----------------------------------------------|
| Запрет действия системы   | *{Субъект} не должен {выполнять действие}.*   |
| Запрет действия участника | *{Участнику} запрещено {выполнять действие}.* |

| ID          | Пример                                             |
|-------------|----------------------------------------------------|
| E.RUTF.0830 | Замена конструкции *не допускается* явным запретом |

В следующем предложении запрет выражен конструкцией *не допускается*.

```markdown
Изменение утвержденного отчета не допускается.
```

Участник должен быть назван, а запрет должен быть выражен словом *запрещено*.

```markdown
Пользователю запрещено изменять утвержденный отчет.
```

### Выбор вида глагола

| ID          | Требование                                                                                       |
|-------------|--------------------------------------------------------------------------------------------------|
| R.RUTF.0900 | Однократное действие с определенным результатом должно быть выражено глаголом совершенного вида. |
| R.RUTF.0910 | Постоянная функция или повторяющееся действие должно быть выражено глаголом несовершенного вида. |

| ID          | Пример                                                       |
|-------------|--------------------------------------------------------------|
| E.RUTF.0920 | Выражение однократного результата глаголом совершенного вида |

В следующем требовании глагол *формировать* обозначает процесс или повторяющуюся функцию.

```markdown
После завершения проверки система должна формировать протокол.
```

Если требование устанавливает получение одного протокола по результатам проверки, должен использоваться глагол совершенного вида.

```markdown
После завершения проверки система должна сформировать протокол.
```

| ID          | Пример                                                    |
|-------------|-----------------------------------------------------------|
| E.RUTF.0930 | Выражение постоянной функции глаголом несовершенного вида |

В следующем требовании глагол *зарегистрировать* обозначает однократное действие.

```markdown
Система должна зарегистрировать все попытки входа.
```

Если регистрация является постоянной функцией системы, должен использоваться глагол несовершенного вида.

```markdown
Система должна регистрировать все попытки входа.
```
